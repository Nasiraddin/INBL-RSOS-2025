# INBL Engine Code for RSOS Paper

Paper title: “EXPLORATION OF THE NON-ZERO UNIVERSE IN INSTANTANEOUS NOISE-BASED LOGIC” (Manuscript ID: RSOS-242285)
Authors: Nasir Kenarangui, Laszlo Kish, Arthur Powalka
Journal: Royal Society Open Science (RSOS)
Date: 07/23/25
Version: 1.0

Overview

This repository contains the INBL Engine code that implements the algorithms and methods described in the RSOS paper “EXPLORATION OF THE NON-ZERO UNIVERSE IN INSTANTANEOUS NOISE-BASED LOGIC”.  
The code generates the numerical results and output data files presented in the paper's figures (Figures 1–10).

The program is consolidated into a single executable with configurable modes corresponding to different analyses and figures in the paper.

Contents

/src/               Source code files (.cpp, .h)
/output/            Example output files matching paper figures
README.md           This documentation file

Requirements

- A C++ compiler supporting C++11 or later (e.g., g++, clang++, MSVC)
- Standard C++ library
- No additional dependencies required

Building the Code

1. Navigate to the /src directory:

   cd src

2. Compile using your preferred compiler. Example (GCC):

   g++ -std=c++11 -O2 -o INBL_Engine.cpp

Running the Program

Since there is no command-line interface, users should:

- Modify input parameters and settings directly in the source code files where variables are clearly documented with comments.
- Rebuild the executable after making parameter changes.
- Run the executable without additional runtime arguments:

   ./INBL_Engine

Outputs will be written to the /output/ directory with filenames clearly corresponding to each figure's data.

Input Data

- There are **no separate input files**.
- All input parameters and data used for simulations are fully described in the paper’s text.
- Default or example input values are set in the source code and documented with comments for easy modification.

Output Data

- The /output/ directory contains output text files generated by the program.
- Filenames include figure numbers and mode to assist identification.
- These output files are sufficient to reproduce the figures presented in the paper.

Notes and Caveats

- Some functions or modules and example problems present in the codebase are not directly used by the paper’s analysis.
- The code does not perform extensive input validation; users modifying the code should follow input specifications described in the paper. Such as the binary number used to generate the hyperspace vector must match the bit resolution parameter N.
- Computationally expensive functions are not used to avoid excessive runtimes.
- Note: To generate Figures6-9 clock cycles for the RTW was set to 5000 instead of the default 2000.
